# visomd MVP plan

`viso FILE.md` (or `cat FILE.md | viso`) prints a Markdown document to a kitty-protocol terminal. Prose is styled terminal text, wrapped to the terminal width. Every `$...$` becomes a one-row image on the text baseline and every `$$...$$` a multi-row image, both typeset by RaTeX in-process and placed with kitty Unicode placeholders. No runtime dependencies: one binary, fonts embedded.

## Settled decisions

- Math engine: RaTeX (`ratex-parser`, `ratex-layout`, `ratex-render` with `embed-fonts`). Pure Rust, KaTeX-compatible LaTeX, no Typst, no TeX install.
- Rasterizer: `ratex-render` gives PNG bytes only, so inline baseline alignment decodes that PNG and composites onto a row-height canvas (port of the sizing logic in `~/repos/jotter/src/latex.rs`).
- Markdown: `pulldown-cmark` with `ENABLE_MATH`, which yields `Event::InlineMath` and `Event::DisplayMath`.
- Styled elements: headings, emphasis, inline code, fenced code with `syntect` highlighting, lists, blockquotes, links, horizontal rules. Tables, images, footnotes are printed as plain text.
- Fallback without graphics (or `--no-images`): print the raw LaTeX.
- Math ink color: query the terminal with OSC 10 at startup, `--fg RRGGBB` overrides.
- Output: one-shot, everything on stdout, image transfers interleaved with text. Not a pager.
- CLI: `clap` derive. Flags only, no config file: `viso [FILE|-] [--no-images] [--fg RRGGBB] [--width N] [--max-width N] [--display-scale F] [--theme NAME]`; persistent values in `~/.config/visomd/config.toml`.
- Wrapping: viso wraps to the terminal width; continuation lines keep list and quote indentation; a formula is an unsplittable token of known column width.
- Terminal access: `libc` for `TIOCGWINSZ` and termios raw mode. All terminal queries go through `/dev/tty`, never stdin, because stdin may carry the document.

## Dependencies

```toml
[dependencies]
clap = { version = "4", features = ["derive"] }
libc = "0.2"
pulldown-cmark = { version = "0.13", default-features = false }
ratex-parser = "0.1.15"
ratex-layout = "0.1.15"
ratex-types = "0.1.15"
ratex-render = { version = "0.1.15", features = ["embed-fonts"] }
png = "0.17"
syntect = { version = "5", default-features = false, features = ["default-fancy"] }
```

`png` 0.17 is already in `ratex-render`'s tree, so pinning the same major adds nothing. `syntect` must use `default-fancy`, not the default `default-onig`, which links the C library oniguruma. Measured: the RaTeX stack plus pulldown-cmark and libc is 87 crates; clap and syntect add roughly 45 more.

## Pipeline

```
stdin or file ──► pulldown-cmark events ──► Vec<Block> ──► wrap + style ──► stdout
                                                 │
                       $..$ / $$..$$ ────────────┴──► ratex ──► PNG ──► decode ──► row-aligned canvas ──► PNG ──► kitty APC + placeholder cells
```

## Modules

### `term.rs` (libc only)

- `Tty::open()` opens `/dev/tty` read-write. Everything below uses that fd.
- `size() -> (cols, rows, cell_w_px, cell_h_px)` from `TIOCGWINSZ`: `ws_col`, `ws_row`, `ws_xpixel / ws_col`, `ws_ypixel / ws_row`. If the pixel fields are zero the terminal cannot do graphics; fall back to text. If stdout is not a tty, use `--width` or 80 columns.
- `query(request, terminator) -> Option<Vec<u8>>`: put the tty in raw mode (clear `ECHO | ICANON`, set `VMIN = 0`, `VTIME = 2` for a 200 ms read timeout), write the request, read until the terminator or timeout, restore termios in all paths (a guard struct with `Drop`).
- `fg_color() -> Option<[u8; 3]>`: request `ESC ] 10 ; ? ESC \`, reply `ESC ] 10 ; rgb:RRRR/GGGG/BBBB ESC \` (also accept a BEL terminator). Take the high byte of each 16-bit channel.
- `supports_graphics() -> bool`: request `ESC _ G i=31,s=1,v=1,a=q,t=d,f=24;AAAA ESC \`, true if the reply contains `i=31;OK`.

### `md.rs` (pulldown-cmark → blocks)

```rust
enum Block { Heading(u8, Vec<Inline>), Paragraph(Vec<Inline>), Code { lang: String, text: String }, List { ordered: Option<u64>, items: Vec<Vec<Block>> }, Quote(Vec<Block>), Rule, DisplayMath(String) }
enum Inline { Text(String), Emph(Vec<Inline>), Strong(Vec<Inline>), Code(String), Link { text: Vec<Inline>, url: String }, Math(String), Break }
```

A single stack-based walk over the event stream. `Event::DisplayMath` inside a paragraph that contains nothing else becomes `Block::DisplayMath`; otherwise it is treated like inline math.

### `math.rs` (RaTeX → canvas)

```rust
struct Canvas { w: u32, h: u32, rgba: Vec<u8> }   // straight alpha, transparent background
fn inline(tex: &str, cell_h: u32, fg: [u8; 3]) -> Option<Canvas>   // h == cell_h exactly
fn display(tex: &str, cell_h: u32, max_w: u32, fg: [u8; 3]) -> Option<Canvas>   // h == k * cell_h
```

Steps, same for both: `ratex_parser::parser::parse` → `LayoutOptions::default().with_style(MathStyle::Text | Display).with_color(fg)` → `layout` → `to_display_list`, which carries `width`, `height`, `depth` in em → `ratex_render::render_to_png(&list, &RenderOptions { font_size: em_px, padding: 0.0, background_color: transparent, device_pixel_ratio: 1.0, .. })` → `png::Decoder` → blit onto the canvas at the computed offset → `png::Encoder` for the transfer. `None` on any parse or render failure, the caller prints the raw LaTeX.

Inline placement, constants from jotter, with `row = cell_h`:

```
em       = 0.9 * row                       # x-height of the math font ≈ terminal x-height
baseline = 0.77 * row                      # from the top of the row
fits     = height*em <= baseline && depth*em <= row - baseline
if fits:  top = baseline - height*em
else:     em  = min(em, 0.96*row / (height + depth));  top = (row - (height+depth)*em) / 2
cols     = ceil(width*em / cell_w);  canvas width = cols * cell_w   # pad right to a cell boundary
```

Display placement: `em = 0.9 * row * scale` with `--display-scale` (default 1, the inline size), scale down if `(height+depth)*em > 4*row` or `width*em > max_w`, canvas height rounded up to whole rows, ink centered vertically, left-aligned horizontally. Display formulas are never wrapped.

### `kitty.rs` (protocol, no crates)

- `transmit(id: u32, png: &[u8], cols: u16, rows: u16) -> String`: base64 the PNG and emit chunks of at most 4096 base64 bytes: first chunk `ESC _ G a=T,U=1,f=100,q=2,i=<id>,c=<cols>,r=<rows>,m=1;<data> ESC \`, middle chunks `ESC _ G m=1;<data> ESC \`, last chunk `m=0`. `U=1` makes it a virtual placement, so nothing is drawn until placeholder cells appear. `q=2` suppresses replies, which matters because stdout is not read back.
- `placeholder(id: u32, cols: u16, rows: u16) -> Vec<String>`, one string per row: `ESC [ 38 ; 2 ; R ; G ; B m` where `id = R<<16 | G<<8 | B`, then `cols` cells of `U+10EEEE` + row diacritic + column diacritic, then `ESC [ 39 m`. Ids stay below 2^24 so the third diacritic is never needed.
- Diacritics table: the 297 code points in `rowcolumn-diacritics.txt` from the kitty docs, shipped locally at `/nix/store/*-kitty-0.49.1/share/doc/kitty/html/_downloads/*/rowcolumn-diacritics.txt`. Row `n` and column `n` both use entry `n`. Copy it into a `const [char; 297]`.
- Image ids: one xorshift generator seeded from the clock, ids drawn from `1..2^24`, unique within the run. Never deleted; kitty evicts by its own quota.
- Base64: a 20-line encoder in this module, with a unit test against RFC 4648 vectors.

### `render.rs` (ANSI text, wrapping, highlighting)

- Walks `Vec<Block>` with a prefix stack: `"  "` per list level, `"│ "` per quote level, bullet or number on the first line of an item only.
- Inline content is flattened into tokens `Word(String, style)`, `Space`, `Math(cols, transfer, placeholder_row)`. Greedy word wrap at `width - prefix_len`; a `Math` token has width `cols` and is never split. If a formula is wider than the available width it goes on its own line.
- When a line containing math is emitted, its transfer strings are written first, then the line text. Placeholder cells are inside the line text, so they wrap and scroll with it.
- Styles via SGR only: heading level 1 and 2 bold plus a color, emphasis `3`, strong `1`, inline code a distinct foreground, links as text followed by the URL in dim. Rule is `─` repeated to the width.
- Code blocks: `syntect::parsing::SyntaxSet::load_defaults_newlines()`, `ThemeSet::load_defaults()`, `--theme` default `base16-ocean.dark`, `HighlightLines` per line, `as_24_bit_terminal_escaped`, indented two spaces, reset at the end of every line. Unknown language falls back to plain text.
- Display math block: a blank line, the placeholder rows prefixed like any other block line, a blank line.
- Fallback: with images off, `Math(tex)` renders as the token `$tex$` and `DisplayMath` as a plain paragraph `$$ tex $$`. Also used per formula when RaTeX fails, with a one-line warning on stderr.

### `main.rs`

clap `Args`. Read the document. Open the tty, get size, color and graphics support, decide `images = !no_images && supports_graphics && cell_h > 0`. Render, write to a `BufWriter` on stdout, flush. Exit non-zero only on unreadable input.

## Order of work

Each step leaves something runnable and checkable in kitty.

1. `term.rs`: a `--debug-term` print of cols, rows, cell size, fg, graphics support. Check against `kitten icat --print-window-size` and your theme's foreground.
2. `kitty.rs`: transmit a solid 3×1-cell canvas and print it in the middle of a sentence. Check that it sits inline and survives a window resize. Unit test the base64 encoder and the placeholder bytes for `id=1, 2×1 cells` against the bytes `kitten icat --unicode-placeholder` emits.
3. `math.rs`: render `x`, `\frac{1}{x^2}`, `\int_0^\infty dx`, `\left(n+\tfrac12\right)` as inline canvases. Port jotter's tests: height equals the row, ink touches the left and right edges, `x` and `x = 1` share a baseline.
4. `md.rs`: parse `tests/fixture.md` and assert the block tree.
5. `render.rs` with `--no-images`: wrapping, prefixes, styles. A snapshot test comparing the output for the fixture at width 60 to a checked-in expected file.
6. Wire math into `render.rs`. Manual check with a real DiagMC note.
7. syntect code blocks.

## Test fixture

`tests/fixture.md`: two heading levels, a paragraph with emphasis, strong, inline code, a link, and three inline formulas including one too tall for the baseline; a display formula; a nested ordered-in-unordered list; a blockquote containing math; a Rust code block; a rule.

## Known ceilings

- ponytail: no cache of rendered formulas; every run re-renders. Add a `~/.cache/visomd` keyed by hash of (tex, cell_h, fg) if a long document is noticeably slow.
- ponytail: wrapping width counts chars, not display width. Add `unicode-width` when CJK or emoji prose misaligns.
- No tmux passthrough, no sixel or iTerm2 protocol, no WezTerm quirks handled.
- Piping into `less` shows image escapes as garbage; a `--tty` mode that sends transfers to `/dev/tty` is a small later addition.
- Image memory on the terminal side grows with document length until kitty evicts; a `viso` run never deletes its images.
