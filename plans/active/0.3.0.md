# visomd 0.3.0 plan

One change: the pager is viso's own.

## Why

With less, the text was laid out once at the starting width; a narrower window made less wrap the lines itself, which splits placeholder rows and garbles every display formula wider than the window. less cannot tell viso where it is, so a re-layout could not restart it at the same place. The 0.2.1 workarounds for kitty (`-X`, no reverse-index, the placeholder character definition, less 632) all served that setup.

## Design

- `pager.rs`: the rendered lines on the alternate screen, keys from `/dev/tty`, whole-screen draws with cursor moves and erase-to-end-of-line, never a terminal scroll. Keys: `j`/`k`, space/`b`, `d`/`u`, `g`/`G`, arrows, page keys, home/end, the mouse wheel through kitty's arrow-key translation, `/` with `n`/`N` for a case-insensitive substring search, `q` or Ctrl-C to quit.
- On SIGWINCH, after the size settles, the old images are deleted by id, the document is rendered again at the new width, and the top line is mapped to the same block and offset. `Renderer::render_blocks` reports each block's first line for that.
- `$PAGER` is no longer consulted. `--tty` remains for a pager of your own, with the less recipe from 0.2.1 in the README.

## Ceilings

- Search has no highlighting and no regular expressions.
- Code blocks wider than the window are clipped, not wrapped (auto-wrap is off so a long line cannot shift the screen).
- A re-layout typesets every formula again and re-sends the images, so a resize costs one full render.
